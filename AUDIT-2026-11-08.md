# Code audit — November 8, 2026

Reviewed the current working tree, including the recent uncommitted account,
profile, wallet, hand-history, engine, and interface changes. Existing work was
preserved. No live database, node configuration, or deployed service was changed.

## Bugs fixed

- **Private socket delivery:** personalized game states, dealt-card messages,
  personal hand histories, and wallet notifications now require a current
  session for the mapped identity. Revoked, expired, rotated, or mismatched
  sessions cannot keep receiving private updates through an old socket mapping.
- **Socket identity:** a seated socket cannot switch identities or become an
  anonymous observer while retaining its seat. Gameplay requests must target its
  seated table. Authenticated chat also rejects revoked sessions.
- **Idle kicks:** removing a player clears their old kick timer, preventing it
  from removing a later seat belonging to the same identity. Empty tables clear
  scheduled hand starts so retired instances cannot overwrite replacement state.
- **Departure updates:** deferred removals broadcast the freed seat even when
  too few players remain for another hand. Idle removals release stale socket
  seat mappings and keep connected clients receiving observer state.
- **Internal account returns:** returning a table stack remains available while
  LND is unavailable. It still uses the existing atomic account/snapshot
  transaction and does not dispatch a Lightning payment.
- **Repeated return requests:** attempts during an active hand keep the player
  marked to sit out next hand; retrying no longer toggles the flag off.
- **Wallet readiness:** malformed, missing, fractional, negative, or non-finite
  node balances fail the solvency check and trip the breaker.
- **Table validation:** configuration keys have no inherited object properties;
  `__proto__` and `constructor` cannot create unconfigured tables.
- **Pagination:** negative hand-history and abuse-log limits cannot disable
  SQLite's result limit.
- **Nginx template:** explicit manifest/admin routes reach the backend instead
  of the landing page. Well-known requests forward the client IP and protocol,
  allowing per-client Lightning-address rate limits behind the proxy.
